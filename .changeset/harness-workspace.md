First release: Git workspaces for AI SDK harness agents. `createWorkspace({ source })` checks a repository out for each session of any `HarnessAgent` — Claude Code, Codex or another runtime — in the working directory the harness makes for it: a Git worktree on a branch of its own, `session/<id>`, so several sessions work side by side on one repository in one sandbox. `withWorkspace(settings, workspace)` gives the agent the `sandboxConfig.onSession` that makes the checkout before the agent starts, and `workspace.sandboxes()` wraps the `sharedSandbox()` or `sandboxPerSession()` of `ai-sdk-harness-sessions`: a suspended session keeps its checkout and finds it again when it resumes, a closed one has it removed. `workspace.open()` does the same for a session you start yourself.

The code comes from `gitRepository({ url, ref, credentials })`, fetched in the sandbox, a private repository's token kept out of it through the sandbox's credential brokering; from `hostRepository({ path })`, a repository of your server sent to the sandbox as Git bundles of what it lacks, with no credential in the sandbox at all; or from `sandboxRepository({ path })`, one already in the sandbox, such as a read-only mount. `setup` commands run in each new checkout, `pnpm install` for instance.

`workspace.session(id)` is the checkout of a live session: `changes()` reads everything the agent changed since the checkout started, its commits included, as a binary patch `git apply` takes, without touching the agent's index; `changedFiles()` lists the files with their line counts; `run()` runs a command in the checkout; `writeLocalFile()` writes a file kept out of the changes. `workspace.fromSandbox()` finds the checkout from the sandbox a tool is given. `WorkspaceError`, `WorkspaceLostError` and `WorkspaceSetupError` say what went wrong, with an `isInstance()` that works across copies of the package.
