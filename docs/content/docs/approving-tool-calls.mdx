This guide starts from the chat of [Managing sessions](/docs/managing-sessions) and puts a person in its loop: the agent's harmless commands run at once, the ones you forbid are refused, and the rest wait for the user — who can allow them for the rest of the conversation. Every rule is in the [package's documentation](/docs/packages/harness-approval).

<Steps>
<Step>

### Install the package

```bash
pnpm add ai-sdk-harness-approval
```

</Step>
<Step>

### Write the policy

What runs at once, what is refused, and what asks: the most restrictive matching rule wins, and `default`, `ask` unless you say otherwise, decides the rest.

```ts title="lib/approval.ts"
import { defineApprovalPolicy } from 'ai-sdk-harness-approval';

export const policy = defineApprovalPolicy({
  commands: {
    allow: ['ls', 'cat', 'pwd', 'git status', 'git diff', 'pnpm test'],
    deny: [
      { match: 'git push', reason: 'The application publishes the changes.' },
      { match: 'rm -rf', reason: 'Nothing is deleted recursively.' },
    ],
  },
  edits: { deny: [{ match: '.env*', reason: 'Environment files stay as they are.' }] },
});
```

A command made of several, `cd app && rm -rf dist`, is held to the rules command by command, substitutions included; one that writes to a file with `>` always asks. See [How rules read](/docs/packages/harness-approval#how-rules-read).

</Step>
<Step>

### Make the agent ask

`policy.agentSettings(harness)` gives the agent the permission mode its policy needs: here `allow-reads`, Claude Code asking before each edit and each command.

```ts title="lib/sessions.ts"
const agent = new HarnessAgent({ harness, model, ...policy.agentSettings(harness) });
```

Codex cannot ask before using its own tools yet ([vercel/ai#22550](https://github.com/vercel/ai/issues/22550)): it gets `allow-all`, and `policy.warnings(harness)` says which rules it does not follow.

</Step>
<Step>

### Let the policy answer

The `approve` option of the session manager asks the policy first. What it decides is answered at once, and the turn goes on in the same stream; what it leaves to the user keeps the session `awaiting-input`.

```ts title="lib/sessions.ts"
import type { ApprovalGrant } from 'ai-sdk-harness-approval';

export const sessions = createSessionManager<{ title: string; grants?: ApprovalGrant[] }>({
  agent: () => agent,
  sandboxes,
  approve: policy.approver({ grants: ({ session }) => session.metadata.grants }),
});
```

![A command allowed by the policy, one refused, one waiting for approval](/screenshots/next-chat/policy.png)

</Step>
<Step>

### Show the requests

`ToolApproval` shows a tool call that asks — "Run a command?", the command — with Deny, Always allow and Approve, and the verdict once given, with its reason. Add it from the [registry](/docs/ui-components):

```bash
npx shadcn@latest add https://ai-sdk-harness.pages.dev/r/tool-approval.json
```

```tsx title="components/chat.tsx"
<ToolApproval part={part} onRespond={respond} />
```

`respond` keeps the grants of "Always allow" with the conversation, then answers:

```ts
async function respond({ approvalId, approved, grants }: ToolApprovalResponse) {
  if (grants)
    await fetch(`/api/sessions/${id}/grants`, { method: 'POST', body: JSON.stringify({ grants }) });
  addToolApprovalResponse({ id: approvalId, approved });
}
```

```ts title="app/api/sessions/[id]/grants/route.ts"
import { withGrants } from 'ai-sdk-harness-approval';

export async function POST(request: Request, { params }: { params: Promise<{ id: string }> }) {
  const { grants } = await request.json();
  const session = await sessions.update((await params).id, {
    metadata: (metadata) => ({ ...metadata, grants: withGrants(metadata.grants, grants) }),
  });
  return Response.json(session);
}
```

A grant allows what the policy would ask about, never what it denies.

</Step>
<Step>

### Answer the agent's questions

Claude Code asks its questions with `AskUserQuestion`: the turn waits for the answers. `QuestionsForm` shows them, and gives the answers as the tool's output:

```tsx
<QuestionsForm
  questions={part.input}
  onSubmit={(output) =>
    addToolOutput({ tool: 'askUserQuestions', toolCallId: part.toolCallId, output })
  }
/>
```

![The agent's questions, answered from a form](/screenshots/next-chat/questions.png)

`useChat` sends the conversation back once everything is answered, approvals and questions; the route continues the turn with `sessions.continue(id, { message })`. Send automatically only when the user answered something: an approval the policy answered within the turn is already taken care of.

```ts
const answered = useRef(false);
useChat({
  sendAutomaticallyWhen: ({ messages }) => {
    if (!answered.current) return false;
    const complete =
      lastAssistantMessageIsCompleteWithApprovalResponses({ messages }) ||
      lastAssistantMessageIsCompleteWithToolCalls({ messages });
    if (complete) answered.current = false;
    return complete;
  },
});
```

</Step>
</Steps>

<Callout type="warn">
  The rules are a guard rail, not a sandbox: `bash -c`, `xargs` or a script the agent wrote run what
  they run. Allow what you trust, and keep the agent in a sandbox. A Claude Code session that
  resumed after a suspension does not take the answers to its approvals
  ([vercel/ai#22549](https://github.com/vercel/ai/issues/22549)): the manager leaves such a repeated
  approval to the user rather than answer it forever.
</Callout>
