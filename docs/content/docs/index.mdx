The [AI SDK harnesses](https://ai-sdk.dev/docs/ai-sdk-harnesses/harness-agent) drive a coding-agent runtime (Claude Code, Codex, OpenCode…) from your application, through a `HarnessAgent`. This project publishes community packages for it, under the `fpasquet` npm account, of two kinds:

- **Sandboxes**: where the agent runs. Every command and file operation of the agent happens there, and the credentials stay outside.
- **Plugins**: what the agent can do. Tools, skills, rules, slash commands, hooks, subagents and MCP servers, bundled into plugins that apply to every runtime.

## Sandboxes

A sandbox package gives `HarnessAgent.createSession({ sandboxSession })` what it expects, a `HarnessV1NetworkSandboxSession`: switching from one to the other is a matter of which function creates it.

| Package                                                        | Where the agent runs                                                                                                       | Status                                 |
| -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| [`ai-sdk-sandbox-sbx`](/docs/packages/sandbox-sbx)             | A [Docker Sandbox](https://docs.docker.com/ai/sandboxes/) microVM (`sbx`), on your machine or in Docker Sandboxes Cloud    | Preview, 0.x (cloud mode experimental) |
| [`ai-sdk-sandbox-cloud-run`](/docs/packages/sandbox-cloud-run) | A [Cloud Run sandbox](https://docs.cloud.google.com/run/docs/code-execution) on Google Cloud, scaled to zero between turns | Preview, 0.x                           |

## Plugins

[`ai-sdk-harness-plugins`](/docs/packages/harness-plugins) (Preview, 0.x) works with any sandbox and any runtime. A plugin is written in code with `definePlugin()`, read from a [Claude Code plugin](https://code.claude.com/docs/en/plugins) directory with `loadClaudeCodePlugin()`, or written as JSON: plugins are configuration, wherever they are kept. A catalog gathers them for a marketplace, where each agent picks whole plugins or single tools, skills, rules, commands, hooks, subagents and MCP servers, with what they require; `withPlugins()` applies what it picked.

| A plugin's…     | What it is                                                           | Claude Code | Codex |
| --------------- | -------------------------------------------------------------------- | :---------: | :---: |
| **tools**       | AI SDK tools run on your server, or commands run in the sandbox      |     ✅      |  ✅   |
| **skills**      | Instructions the agent loads when it judges them relevant            |     ✅      |  ✅   |
| **rules**       | Instructions the agent follows, for every file or some               |     ✅      |  ✅   |
| **commands**    | `/<name>` prompts, expanded on your server                           |     ✅      |  ✅   |
| **hooks**       | Commands the runtime runs at a moment of the session, in the sandbox |     ✅      |  ❌   |
| **subagents**   | Specialists the agent delegates to                                   |     ✅      |  ❌   |
| **MCP servers** | Connected by your server, or run by the runtime in the sandbox       |     ✅      |  ✅   |

![A hook at work in the Next.js example: the agent may not read the .env file](/screenshots/next-chat/item-hook.png)

A hook at work in the [Next.js example](/docs/examples/next-chat): written in JSON with its script, it runs in the sandbox before each read or shell command of Claude Code. It blocked the reading of `.env`, and told the agent why.

## Versioning

Every package is released on its own with [Changesets](https://github.com/changesets/changesets), and is in its **0.x** series: its API settles with the feedback of the people trying it, before a 1.0.0. The public API is what a package exports from its entry point. Until 1.0.0, a minor release (0.1 → 0.2) may break it, and its changelog says how with a `BREAKING:` note; a patch release (0.1.0 → 0.1.1) never does. The caret range npm installs by default, `^0.1.0`, therefore stays on 0.1.x. The AI SDK harnesses are themselves experimental: when their `HarnessV1` interfaces break, the packages follow in their next minor.

From 1.0.0 on, the packages will follow [Semantic Versioning](https://semver.org): breaking changes in a major only, except a feature documented as experimental, such as the cloud mode of `ai-sdk-sandbox-sbx`, which may change in a minor release and says so.

Feedback is what gets the packages to 1.0.0: open an [issue](https://github.com/fpasquet/ai-sdk-harness/issues) for what works, what does not, and what is missing.
